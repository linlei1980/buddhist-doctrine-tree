# 判准充分性校对规范

这一轮查的是一件此前几轮都查不出的事：**释义是否把概念讲清楚了**。

前几轮已经分别校过「说得对不对」（事实、出处、年代）与「译得对不对」（英文）。
那些校对全部通过，但仍存在「正语四条一个都没界定」这类问题——因为**每一句本身都没说错**。
故另立这一轮，只查判准。

## 输入

`build/review_def/d*.json`：数组，每项含

- `id`、`category`、`name`（节点名）、`sa`（梵巴原语）、`era`、`tt`（年代三栏）
- `desc`：释义正文（`\n\n` 分段、`- ` 列项、`**粗体**` 强调、`[[node_id|文字]]` 交叉引用）
- `sources[]`：`t` 出处题名、`q` 引文

## 只查一类问题：读者无法据此判断「什么算、什么不算」

具体表现为以下五种，**任一节点中出现即报**：

1. **列名不界定**——释义列出若干名词（如「不妄语、不两舌、不恶口、不绮语」），
   却未说明各名的判准是什么。读者知道有这四项，但不知道哪句话算两舌。
2. **用未解释的术语解释术语**——如「以无表色成立业相续」，而「无表色」本节点未交代。
3. **判准缺失**——给出了类别，但未给出**区分标准**。例如只说「有五种邪命」并列出五种，
   却不说明「为什么这五种是邪命」。
4. **同名异义未辨**——同一词在此语境下与日常语或他派用法不同，而释义未指出。
   例：「色」不是颜色；「无分别」不是不作判断；「空」不是没有。
5. **成组体例不齐**——同一组（如八正道八支、十二因缘十二支）内，多数成员交代了判准，
   而个别成员只列名。**这类务必报**，因为它与本页自身体例不一致。

## 不要报告

- 事实错误、出处错误、年代错误（前几轮已专校，另有其人负责）
- 排版、标点、译名偏好
- 「应补充某内容」「可以更详细」这类增补建议——**只报缺失的判准，不报缺失的篇幅**
- 交叉引用与粗体的位置（已由脚本全量校验）
- 观点立场之争（本页有意并列宗派分歧）

**重要**：若一个节点虽短，但判准完整（读者读完能判断什么算什么不算），**不要报**。
本页明确「释义深度依各概念的需要而定，不作长度上的齐一」——短而清楚是合格，不是缺陷。

## 输出

写入 `build/review_def/<批次>.findings.json`，JSON 数组，每项：

```json
{
  "id": "节点 id",
  "severity": "high | medium | low",
  "kind": "列名不界定 | 术语未释 | 判准缺失 | 同名异义 | 体例不齐",
  "problem": "一句话说明缺什么（中文）",
  "current": "当前释义中该片段的**原文照抄**（我要用它精确定位，不要改写、不要加省略号）",
  "missing": "缺的是什么判准——请给出你自己知道的界定，并**注明依据**（经论名/卷次；不确定就写「不确定」）",
  "suggested": "建议补入的一句话（不超过 60 字，与本页文体一致：简洁、不作教义评判）"
}
```

- `severity`：`high` = 读者读完仍不知该概念指什么或什么算它；`medium` = 知道大意但无从判断边界；
  `low` = 用词可更准
- 每条只针对一个具体缺口，不要把整个节点的问题合成一条
- `current` 必须是输入文件中的**逐字片段**
- 没有问题的节点不必出现；整批无问题写 `[]`

## 完成回报

输出路径、条数、severity 与 kind 分布，以及你认为最严重的 3 条（附你的依据）。
