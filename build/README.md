## 节点字段

```python
NODES['some_id'] = dict(
    n='名称',                    # 目录与详情标题
    en='sanskrit / pāli',        # 梵巴原语；确无对应写 '—'
    c='core',                    # 分类，见 build.py 的 CATS
    ep='early',                  # 层积：early / develop / folk / modern / meta
    era='前6-5',                 # 年表时段，见 build.py 的 ERAS
    key=1,                       # 可选：标为年表重点节点
    aka=['别名'],                # 可选：用于正文自动互链与检索
    d='释义。空行分段；行首 "- " 渲染为列表；**粗体** 可用。',
    src=[dict(t='《俱舍论》卷1', q='引文')],
    tt=dict(form='思想形成', fix='文献定型', trans='汉译流传'),  # 不适用者整项省略
)
```

释义中的**交叉引用是自动的**：正文与引文中首次出现的其他节点名（两字以上）会自动变成可点击链接，长释义最多 2 个、短释义与引文 1 个，且不会链回本节点。因此新增节点时**不需要手写链接**；单字名（行、识、受、取、有、生、法、空、业、苦…）故意不参与自动链接，以免破坏引文原文，这些概念由详情页的「关联节点」覆盖。

## 修改流程

1. 改 `build/content_*.py`（新增节点）或 `build/build.py` 中的 `TREE`（目录位置）、`ERA_BY_ID`（时段标注）、`E`/`add(...)`（关系）。
2. 运行：

```bash
python3 build/build.py
```

3. 脚本会先做五项校验，任何一项不通过都会打印问题清单：释义为空、无出处、无年代、节点未进目录、关系端点或类型不存在。通过后会输出 `节点 / 关系 / 出处` 三个数字与重新生成的页面。

## 关系类型

223 条原始关系原有 142 种标签（含 12 条以数字 1—12 标注的十二因缘支）。现在统一为十类，原来的具体说法保留在 `note` 字段并显示在「关联节点」行内：

`支分 · 次第 · 因果 · 体同 · 判摄 · 对辨 · 修证 · 层积 · 依据 · 说明`

新增关系在 `build.py` 里用 `add(起点, 终点, 类型, '可选的具体说明')` 一行即可。

## 目录树

`TREE` 是**目录的唯一来源**：节点在目录中的深度即其层级（不再另设 `lv` 字段），同一节点可在多处出现并带 `note`（如「第一支」「另见 05 大乘层」）。校验会保证每个节点至少出现一次。

## 生成结果自检（本次）

- **228 个节点 / 609 条关系 / 542 条出处引证 / 12 层目录 / 9 个年表时段**
- 其中「文献节点」50 个由 `make_doc_nodes()` 自动生成（见下），其余 178 个为人工撰写
- 原版 129 个节点的释义**逐字未改**，原有出处一条未失；仅两处名称修订（`诸法无我 → 诸行是苦`、`涅槃 → 涅槃寂静`）与一处年代口径修订（依「三次结集」条目统一）
- 校验规则：释义为空、无出处、无年代、未进目录、关系端点或类型不存在——文献节点豁免「无年代」一项

## 文献节点（自动生成）

`doc_list()` 把各节点出处里出现的文献归一（去掉卷品号与作者），统计引用次数与类别；`make_doc_nodes()` 为**被 3 个以上节点引用**的文献各建一个节点，挂在第 12 层的「文献」分支下（经／律／论疏／史料四组）。

文献节点只写三件事：类别、本页引用规模、引用它的节点清单；**不写文献自身的年代**。理由见 `make_doc_nodes()` 的文档字符串——用「最早引用它的教义节点」的年代去标注文献，会把《俱舍论》标成「约前 5 世纪」。文献的年代只能由讨论该文献的节点（04 论书层、12 历史 · 传播）给出；`mine_dating()` 会尝试从出处条中提取「唐 玄奘译《俱舍论》（651—654）」这类可靠线索，提不到就留空。

要调整门槛或分组，改 `make_doc_nodes()` 里的 `d['n'] < 3` 判断与 `DOC_GROUP_NAME`。

## 英文版与双语检索（简述）

英文译文与界面文字都在 `build/i18n/` 下：

```bash
python3 build/i18n_build.py     # 从 work/*.en.jsonl 合并译文、统一体例与书名
python3 build/build.py          # 产出 index.html（中文）与 en.html（英文）
```

- `ui.json` —— 界面文字、分类、关系类型、层积的中英对照；新增界面串时在此加键
- `TRANSLATION-SPEC.md` —— 术语表、体例与验收标准，译文以梵文／巴利文为准
- `doc_names.json` —— 同一部经典只保留一种英译（321 种出处条目，构建时校验冲突为 0）
- `nodes.jsonl` / `sources.json` —— 合并产物，不要直接改，改 `work/` 下的分批文件

双语检索的实现：`render.py` 的 `cross_terms()` 为每个节点生成一份**另一语言**的检索词
（名称、梵巴原语含去变音符写法、别名），并入前端的检索索引，不复制释义正文——
中文页因此可搜 `dependent origination`，英文页可搜「缘起」。

文本渲染的 Markdown 只有三种标记：`**粗体**`、`*斜体（书名）*`、`[[node_id|文字]]` 交叉引用。
转换时**先斜体后粗体**，二者可互相嵌套；书写时不要出现 `***`（三颗星歧义，会渲染错）。

## 产物检查（两层）

生成之后有两套检查，分别针对不同的事故类型：

```bash
python3 build/verify_page.py     # 静态断言，零依赖，CI 必跑
node build/verify_page.mjs       # 浏览器实测，本地建议跑（无 Chrome 时自动跳过）
```

**为什么需要它们**　曾经出过一次事故：生成 head 时把 `<style>` 段一并替换掉，页面完全失去
样式——元素退化为块级排列、目录宽达整屏、徽章配色消失。而**内容比对与 JS 检查都发现不了**：
数据完好、脚本无异常、页面能打开，只是难看。故补上这两层。

`verify_page.py` 检查（不依赖浏览器）：

- `<style>` 段恰好一段，且不小于 12 KB、含 `--bg:`、`.node-row`、`.cstep` 与两个媒体查询
- 无未替换的占位符（`__CSS__`、`__UI__`、`{{…}}` 等）
- `html lang`、`canonical`、`description`、`keywords`、`hreflang`、`og:title`、JSON-LD 齐备且可解析
- 内联数据可解析，节点数 ≥ 200、关系数 ≥ 500
- 脚本段含该语言的界面文字；HTML 标签区不残留 `**粗体**` 或 `[[id|…]]` 标记

`verify_page.mjs` 检查（无头 Chrome + CDP，无需额外依赖）：

- 计算样式断言：`body` 为 `flex`、目录宽 398px、徽章有背景色、桌面端隐藏「返回目录」
- 交互断言：统计已填充、目录有节点、节点详情可打开、出处与交叉链接已渲染、
  年表有内容、文献总览可渲染、学习路径有 4 张卡片
- 无 JS 异常

新增样式或界面元素时，把对应的断言加进这两个文件的清单即可。

## 站点地图与抓取规则

`build/make_seo_files.py` 生成 `sitemap.xml` 与 `robots.txt`，由 `build.py` 在主流程末尾调用。
URL 取自 `build/i18n/ui.json` 的 `canonical`，因此站点地图不会与页面里的 canonical 脱节。

- `lastmod` 取 `data/buddhism.json` **最后一次 git 提交的日期**，不用文件 mtime——
  CI 每次检出都会把 mtime 更新为当天，用 mtime 会导致生成结果与仓库内容不一致
- 两个 URL 各自带 `zh-Hans` / `en` / `x-default` 三条 `hreflang`，声明语言关系
- `robots.txt` 里的 Sitemap 行指向仓库内的站点地图（**注意是 `…/buddhist-doctrine-tree/sitemap.xml`**，
  曾经误写成站点根 `…/sitemap.xml`，现已由断言拦住）

改仓库名或换域名时，只需改 `ui.json` 的 `canonical`，两份文件会随之更新；
`verify_page.py` 会断言站点地图的 URL 集合与页面的 canonical 一致。

## 社交分享预览图

`build/make_og_image.py` 生成 `og-image.png`（1280×640），供 `og:image` 与 `twitter:image`
使用。设计与页面同色系：纸白底、朱砂强调色、深墨正文。

- **依赖 Pillow**，而 CI 不安装 Pillow，故本脚本在缺少 Pillow 时**跳过并保留已有图片**，
  不视为失败；图片本身提交进仓库，日常构建无需重新生成
- 需要重新生成时（例如改了数字或文案）：
  `<带 Pillow 的 python> build/make_og_image.py`
- 页面里的 `og:image` 地址与 `canonical` 同域，取自 `ui.json`，换域名时一并更新
- `verify_page.py` 会断言：`og:image` 存在、指向的文件在仓库内、为 1280×640、
  且 `twitter:image` 与 `twitter:card` 齐备

## 英文译文校对（2026-09 全量）

英文版首次完成后做过一次**全量校对**：179 个人工节点分五批，每批由一个独立审读者
逐句比对中文与英文，按「术语 / 引文忠实度 / 英文表达」三类报告问题。审读者的产出
保存在 `build/i18n/review/*.findings.json`，批次输入在 `build/i18n/review/r*.json`，
规范在 `build/i18n/review/REVIEW-SPEC.md`。

报告的索引、各批条数与修正提交见 [`REVIEW-LOG.md`](REVIEW-LOG.md)。

**为什么值得留档**：机器能查的只是结构（覆盖率、出处条数、链接与粗体、中文残留），
而这一轮查出的最严重问题**全在语义层**，机器查不出：

- 「情有理无」的「情」是迷情（众生迷妄的认识），被误译作 affection（贪爱），
  导致遍计所执性与依他起性的定义失真
- 引文漏字：「观无我我所」漏掉第二个「无」，意思正好相反；
  「忧悲恼苦」四项只译出三项（漏「恼」），三批校对各自独立发现了同一句式问题
- 所引定义被换掉：「色者，变坏义」误作 the nature of resistance（那是「质碍」的定义）
- 擅自增补：正文加入中文所无的 *Nyāyamukha*；出处栏给《瑜伽师地论》补了中文没有的卷次

修正分四轮提交（`3543835`、`a98fd17`、`46875e2`、`5781a75`），另做两轮全局规范化：
梵巴术语的变音符（`build/i18n/normalize_en2.py`）、卷次与引号体例、术语择一。

**流程上的两条教训**（都写进了脚本校验）：

1. **不要用零散字符串替换改译文**。我在修正一处嵌套引用时把整段改坏（出现重复与
   错位粗体），此后改为「整段比对—精确重写」，并要求每条替换断言唯一命中。
2. **替换必须排除链接 id**。全局规范化曾把 `[[tathagatagarbha|…]]` 一并改成带变音符的
   id，导致 19 处交叉引用指向不存在的节点——结构断言当场报出，才发现。
   同理，英文正文出现中文字符（把「即」写进英文）也是靠断言拦住的；
   该断言现已进入 `merge_i18n.py`，构建阶段即失败。

**新增术语或改写译文时**，先改 `build/i18n/work/*.en.jsonl`，再跑：

```bash
python3 build/i18n_build.py     # 合并（内含中文残留等断言）
python3 build/build.py          # 重建页面
python3 build/verify_page.py    # 结构复核
```
